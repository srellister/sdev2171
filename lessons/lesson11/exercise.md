# Lesson 11 Take-Home Exercise

## Title
Debugging Workflow Review

## Purpose
This exercise reinforces lesson 11 by asking you to explain one debugging workflow you used, the evidence you checked, and the result of your fix and retest.

## Which bug to write about
Write about the single debugging scenario you investigated during the lesson-11 lab.

Use:
- the instructor-assigned bug from class, or
- the one bug you were told to inspect while using the instructor-guided reference path

Do not invent a new bug for this exercise.

## Before You Start
Use these lesson-11 reference files:
- [debugging-lab-checklist.md](debugging-lab-checklist.md)
- [debugging-reference.md](debugging-reference.md)
- [starter-snippets.md](starter-snippets.md)
- [troubleshooting-checklist.md](troubleshooting-checklist.md)

Helpful lesson-11 terms:
- **bug**: behaviour that does not match the intended result
- **symptom**: the visible or described result of a bug
- **hypothesis**: your current explanation of the bug
- **retest**: running the same check again after one small fix

## Submission Format
Submit a short Markdown or PDF response. Aim for 1 to 2 pages total plus one screenshot.

If you used the instructor-guided reference path because your own project was not ready:
- you may still complete this exercise
- clearly state that you used the reference path
- identify which observations, logs, code comparisons, or repairs were your own work
- include one sentence naming the next step for getting your own project ready for lesson 12

## Tasks
### Part 1: Bug Description
Write 3 to 5 sentences explaining:
- which lesson-11 bug scenario you investigated
- what the bug symptom was
- where it appeared in the app
- what the screen should have done instead

### Part 2: Evidence And Inspection
Describe one debugging check you used.

Include:
- what value, warning, error, DevTools observation, or file you inspected
- why that was the most relevant first check
- what evidence you learned from it

Use at least one real tool clue from this list:
- one exact warning or error line
- one log result from the Expo terminal or DevTools `Console`
- one DevTools observation

### Part 3: Fix And Retest
Describe one small fix you made.

Include:
- what code change you made
- why that change matched your hypothesis
- what happened after the retest

### Part 4: Reflection
Explain:
- one debugging habit from this lesson that you want to keep using in later lessons
- one way that habit will matter when lesson 12 adds remote data and async timing

### Part 5: Screenshot Evidence
Include one screenshot of:
- the warning or error view, or
- the corrected screen after the bug was resolved

Label or caption:
- the bug symptom or the corrected result
- one clue you used during debugging

## Success Criteria
Strong submissions will:
- use bug, symptom, hypothesis, and retest terms accurately at a beginner level
- describe one debugging loop as a step-by-step process
- connect the inspected evidence to the final fix
- include one real tool clue instead of only a general description
- explain one small code change rather than a broad rewrite
- include one required screenshot with a short label or caption
