# Lesson 12 Fetch Status Tracker

Use this tracker at the midpoint or checkpoint if your instructor asks for a quick status update.

## Status options
- `resolved`
  The app fetches remote data, stores it in state, and renders it successfully.
- `partial`
  Part of the request, mapping, or rendering flow works, but the full screen is incomplete.
- `blocked`
  The build cannot continue during class without recovery support.

## Suggested check order
1. endpoint URL
2. trigger location
3. response clue
4. mapped item shape
5. rendered output
6. known-good reference comparison if needed

## Instructor checkpoint question
Be ready to answer:
- When does your request run?
- What clue showed that the request worked or failed?
- What object shape does your list renderer need?
