# Lesson 17 Take-Home Exercise

## Title
Form Draft And Shared Result Review

## Purpose
This exercise reinforces lesson 17 by asking you to explain how the form draft stayed local, how validation worked, and how the committed result became visible across screens.

## Which App Flow To Write About
Write about the lesson-17 form workflow you used during class.

Use:
- your own lesson-17 form app, or
- the instructor-guided reference path if your own project was not ready

Do not invent a different form example for this exercise.

## Before You Start
Use these lesson-17 reference files:
- [forms-build-checklist.md](forms-build-checklist.md)
- [local-vs-shared-form-state.md](local-vs-shared-form-state.md)
- [validation-reference.md](validation-reference.md)
- [starter-snippets.md](starter-snippets.md)
- [troubleshooting-checklist.md](troubleshooting-checklist.md)

Helpful lesson-17 terms:
- **controlled input**: an input field whose value comes from state
- **local draft state**: the form values while the user is still typing
- **validation**: checking whether the form is acceptable before save
- **committed shared data**: the saved result moved into shared state after submit

## Submission Format
Submit a short Markdown or PDF response. Aim for 1 to 2 pages total plus one screenshot.

If you used the instructor-guided reference path because your own project was not ready:
- you may still complete this exercise
- clearly state that you used the reference path
- identify which observations, comparisons, or code notes were your own work
- include one sentence naming the next step for getting your own project ready for lesson 18

## Tasks
### Part 1: Draft State
Write 3 to 5 sentences explaining:
- which form values stayed local while typing
- why those values did not need to become shared immediately

### Part 2: Validation
Write 3 to 5 sentences explaining:
- one validation rule used in this lesson
- what the user sees when that rule fails
- what changes when the form becomes valid

### Part 3: Submitted Shared Result
Write 4 to 6 sentences explaining:
- what data moved into shared state after submit
- which screen saved it
- which screen displayed it later

### Part 4: Data-Flow Reflection
Explain why the lesson used a local-draft then submit-to-shared pattern instead of putting every keystroke into Context.

### Part 5: Screenshot Evidence
Include one screenshot of:
- the form screen with a validation message, or
- the summary screen with the saved session title and count

Label or caption:
- the screen shown
- the clue you used to confirm the form flow

## Success Criteria
Strong submissions will:
- use controlled input, local draft state, validation, and committed shared data terms accurately at a beginner level
- explain one visible validation clue clearly
- distinguish draft state from committed shared state
- explain how the saved result moves across screens
- include one required screenshot with a short label or caption
