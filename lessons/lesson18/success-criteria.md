# Lesson 18 Success Criteria

Use this checklist before you decide that lesson 18 is complete.

## Stable Integrated Workflow
To count as `resolved`, your project should have:

- one working details screen connected to the local backend
- one working shared selected-step update path
- one working form route with controlled inputs
- one visible validation message on invalid submit
- one working valid-submit path
- one summary screen showing the committed saved result
- intentional testing evidence for invalid submit and valid submit

## Explanation Standard
You should also be able to explain:

- which value stayed local while the user typed
- which value was shared after submit
- what visible clue proved validation happened before save
- what visible clue proved the summary screen read the committed result

## Acceptable Incomplete Progress
If the workflow is not fully stable yet, you may still record `partial` only when:

- the current blocker is named clearly
- the exact file or logic area is identified
- one next action is written down

## Not Yet Acceptable
You are still `blocked` if:

- the provider or route path is unclear
- the form route cannot be opened reliably
- validation still does not appear
- the summary screen still cannot read the saved result
- you have no named next action
